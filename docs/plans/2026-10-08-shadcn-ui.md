# Replace the style functions with shadcn/ui: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, in this session, on the branch `feat/shadcn-ui`. Subagents may review; they never implement (see `~/.claude/CLAUDE.md`). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the home-made `cva` style functions in `lib/styles/` with theme tokens and two shadcn/ui components (`Button`, `DropdownMenu`), switch theme handling to `next-themes` and the icons to Lucide, and keep the site looking the same apart from the icon glyphs. This is story #34 of epic #32.

**Architecture:** The work happens in four commits, each leaving a working site:

1. Theme handling moves to `next-themes`. This removes the flash of the wrong theme and persists the choice.
2. The palette becomes semantic theme tokens. The layout and text style functions become plain Tailwind classes.
3. A shadcn `Button` replaces the `button` style function in the navigation.
4. A shadcn `DropdownMenu` with Lucide icons replaces the Headless UI theme selector, and `lib/styles/`, Headless UI and the icon font are deleted.

A fifth commit updates the docs.

**Tech stack:** shadcn/ui CLI 4.21.4 (style `radix-nova`, base Radix), `radix-ui` 1.7, `cn` 0.4 (shadcn's class merger), `lucide-react` 1.53, `next-themes` 0.4.6, on the stack from story #33.

**Spec:** `docs/specs/2026-10-08-repository-overhaul-design.md`, "Story 2". The spec is on `main`.

## Global constraints

- **Static export stays:** no server-only features. `ThemeProvider`, `ThemeSelector` and `ParticleCanvas` are the only client components we write. The generated `components/ui/dropdown-menu.tsx` carries its own `"use client"`.
- **All styling goes through theme tokens.** After Task 2, `@theme` defines no raw colour scales. `primary` and `secondary` mean the shadcn tokens, and stone and yellow survive only as token values.
- **Only `Button` and `DropdownMenu` are added.** No `Card`.
- **`content/layout.json` keeps its shape.** Its theme `icon` values (`snowflake`, `moon`, `sun`) are already Lucide icon names, so they don't change.
- **The look stays the same apart from the theme selector's icons.** The comparison script in Task 1, step 1 measures this.
- **Before each commit,** run `npm run lint`, `npm run typecheck`, `npm test` and `npm run build`. CI is disabled for this repository, so these local runs are the proof.
- **Commit messages:** conventional commits with a lowercase subject. End each with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Push each task commit as soon as it's made.

**Deviations from the spec**, all small; each is noted where it happens:
- **`secondary` is opaque, and `/80` is applied in classes.** The spec's token table has `secondary` at stone-200 at 80%. Here the token is opaque stone-200 (dark: stone-800), and the classes apply the 80% (`bg-secondary/80`). That way `hover:bg-secondary` reproduces the old hover to full opacity.
- **`accent` is stone-300 in light, not stone-200.** It's used only for the hover on dropdown menu items, which was stone-300. With stone-200 the hover would be nearly invisible over the stone-200/80 background.
- **No pointer-capture polyfills.** The spec planned them for Radix in jsdom, but a spike showed Radix's menu works in jsdom with only the existing `ResizeObserver` stub, so `vitest.setup.ts` doesn't change.
- **The `default` button variant hovers with `bg-primary/80`.** No page uses this variant. The old stone-800 hover would need a raw colour scale, which the token-only rule rules out.

## Review focus

1. **Hard reload with dark mode chosen:** the page must render dark from the first paint, with no flash of light. Pinned in Task 1, steps 8 and 10 (the inline script is in the HTML, and a browser check).
2. **First visit with no stored choice:** the theme follows the system setting, and the selector reads "system". Pinned by Task 1's tests (`defaultTheme="system"`, `enableSystem`).
3. **Keyboard use of the theme menu** (Enter to open, arrow keys, Enter to choose, Escape to close without change). Pinned in Task 4, step 1.
4. **Theme change on the home page:** the particles recolour, using `resolvedTheme`, so "system" resolves to light or dark. No second canvas appears. Pinned by the browser check in Task 1, step 10.
5. **Visual parity after moving to tokens:** the computed colours, fonts and sizes of the nav buttons, theme button, heading, footer link and footnote match today's build in light and dark. Pinned by the comparison in Tasks 2, 3 and 4.

```tsx
'use client'

import { Moon, Snowflake, Sun } from 'lucide-react'
import { useTheme } from 'next-themes'
import { useSyncExternalStore } from 'react'

import { Button } from '@/components/ui/button'
import {
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuRadioGroup,
  DropdownMenuRadioItem,
  DropdownMenuTrigger,
} from '@/components/ui/dropdown-menu'

const icons = { moon: Moon, snowflake: Snowflake, sun: Sun }

const subscribe = () => () => {}

type ThemeOption = {
  icon: string
  name: string
}

type ThemeSelectorProps = {
  options: ThemeOption[]
}

export const ThemeSelector = ({ options }: ThemeSelectorProps) => {
  const { theme, setTheme } = useTheme()
  const isHydrated = useSyncExternalStore(
    subscribe,
    () => true,
    () => false,
  )
  const current = isHydrated ? (theme ?? 'system') : 'system'

  return (
    <DropdownMenu>
      <DropdownMenuTrigger asChild>
        <Button variant="secondary">
          <Sun className="dark:hidden" />
          <Moon className="hidden dark:block" />
          {current}
        </Button>
      </DropdownMenuTrigger>
      <DropdownMenuContent>
        <DropdownMenuRadioGroup value={current} onValueChange={setTheme}>
          {options.map(({ icon, name }) => {
            const Icon = icons[icon as keyof typeof icons]

            return (
              <DropdownMenuRadioItem key={name} value={name}>
                {Icon && <Icon />}
                {name}
              </DropdownMenuRadioItem>
            )
          })}
        </DropdownMenuRadioGroup>
      </DropdownMenuContent>
    </DropdownMenu>
  )
}
```
